Content Opportunity Scoring for Search Performance

A machine-learning approach for prioritising content pages for human review and possible refresh.

FlyRank ML Internship Capstone

Abstract

This project asks whether search-performance signals can be used to identify content that may need review or refresh.

I compared Logistic Regression and Random Forest with a frozen Week-4 baseline using a client-grouped holdout evaluation.

The Random Forest achieved 0.90 Precision@20 and 0.70 Precision@50, while Logistic Regression achieved 0.70 and 0.68 respectively.

The baseline achieved 0.20 Precision@20 and 0.30 Precision@50.

The results suggest that the Random Forest can help prioritise a small content-review queue, but the model is a decision-support tool and does not prove that refreshing a page will improve its search performance.

1. Introduction / Problem Statement

Content teams often have more pages to review than they have time to inspect manually. This creates a practical prioritisation problem: which pages should be looked at first?

This project focuses on Content Opportunity Scoring. The goal is to rank pages using available search and content-performance signals so that a content team can focus its limited review time on the highest priority pages.

The system does not automatically decide that a page should be refreshed. Instead, it produces a ranking that can support a human review process.

2. Data

The analysis uses the anonymized FlyRank ML Internship dataset. The dataset contains 30,000 rows across 32 clients and 44 original columns.

Six page-level signals were used as model features:

  • 90-day impressions
  • Days since last update
  • Content age
  • Average search position
  • Click-through rate (CTR)
  • Engagement rate

For evaluation, a declining-page proxy was created from trend_direction. Pages with a "down" trend were treated as declining.

This is an evaluation proxy. It does not mean that a page definitely needs a refresh, and it does not measure whether refreshing a page would improve performance.

3. Methodology

Models

Two machine-learning models were compared:

  • Logistic Regression
  • Random Forest

Both models were compared with the frozen Week-4 baseline.

Validation

A client-grouped 75/25 holdout split was used. This kept pages from the same client together instead of allowing the same client to appear in both training and testing.

The split contained 24 training clients and 8 test clients, with zero client overlap.

Leakage control

Outcome-derived and identifying fields such as trend_direction, trend_pct, client_id, and content_id were not used as model features.

Ranking

The Random Forest produces a probability score for the declining class. Pages can then be ranked by this score to create a review priority list.

The results show that Random Forest produced the strongest ranking performance on the held-out client split.

90-day impressions had the highest feature importance, followed by content age and average position.

Feature importance describes how the model used the available features. It should not be interpreted as evidence that changing a feature will cause better search performance.

5. Limitations & Honest Framing

The model was evaluated on one client-grouped holdout split. The results therefore describe performance on this evaluation split and should not be treated as a guarantee of future results.

The target is a proxy based on observed trend direction. It does not directly measure whether a page should be refreshed.

The available timestamp information does not allow me to fully prove that every feature window is non-overlapping with the label window.

The model identifies patterns associated with declining pages. It does not prove that refreshing a page will cause its search performance to improve.

For these reasons, the model should be used for decision support and human review rather than automatic content changes.

6. Ranked Recommendations

The model output is intended to create a ranked review queue. Pages with higher scores should generally be considered earlier when review capacity is limited.

  1. Review high-scoring pages with meaningful search visibility for a possible content refresh.
  2. Review visible pages with weaker CTR for possible metadata or content improvements.
  3. Monitor moderate-score pages rather than changing them immediately.
  4. Leave stable pages alone unless there is another clear editorial or business reason to review them.

Human review

Before taking action, a reviewer should check the page context, business importance, recent changes, seasonality, factual accuracy, and whether there is a useful editorial improvement to make.

What should not be automated

  • Publishing content
  • Deleting content
  • Merging or redirecting pages
  • Legal or compliance decisions
  • Pricing decisions
  • Final brand or messaging decisions
